# WearTwin Simulation

**ESP32 • Wokwi • FreeRTOS • MPU6050 • Simulated ECG • Kalman Filtering**

## Overview

`simul_weartwin` is the Wokwi simulation component of **WearTwin**, a digital-twin-oriented prototype for monitoring physiological and motion signals.

The simulation combines:
- **MPU6050 motion sensing** for inertial measurements and orientation estimation.
- **A custom ECG simulator chip** that generates a synthetic ECG-like analog waveform.
- **ECG signal processing** that filters the waveform, detects candidate R-peaks, and calculates RR intervals and average BPM.
- **A Kalman filter** that combines gyroscope rate and accelerometer-derived angle to estimate orientation.
- **ESP32 FreeRTOS tasks** that separate ECG acquisition from IMU acquisition.

This folder is a simulation and firmware prototype. The ECG waveform is generated in software; it is not a real patient's ECG and does not establish medical validity.

## Simulation Architecture

```text
Wokwi ECG Simulator Chip
  └── Synthetic analog ECG output ──> ESP32 GPIO 34
                                      └── CardialState
                                          ├── 250 Hz sampling target
                                          ├── 2000-sample buffer (8 seconds)
                                          ├── 35 Hz low-pass filter
                                          ├── R-peak detection
                                          └── RR intervals and average BPM

Wokwi MPU6050 ── I²C (SDA 21, SCL 22) ──> InertialState
                                          └── KalmanFilter
                                              ├── Angle estimate
                                              └── Gyroscope-bias estimate

ESP32 FreeRTOS:
  Core 0 ── ECG acquisition task
  Core 1 ── IMU angle acquisition task

Main loop ── Serial status output
```

The main application targets an ECG sampling interval of 4 ms (250 Hz) and an IMU update interval of 10 ms (100 Hz). ECG processing runs after a complete 2000-sample window has been collected, which corresponds to approximately 8 seconds at 250 Hz.

## Running the Simulation

1. Open the [WearTwin Wokwi project](https://wokwi.com/projects/477754690630501377).
2. Start the simulation.
3. Use the ECG Simulator chip's **Heart Rate (BPM)** control to change the synthetic waveform's configured rate (40–180 BPM).
4. Open the serial monitor and observe the initialization messages and periodic status output.
5. Wait for the ECG acquisition buffer to fill before expecting processed R-peak, RR-interval, and average-BPM results.

The main sketch uses `Serial.begin(115200)`. The periodic status line reports the estimated IMU angle, estimated gyroscope bias, and the average BPM calculated from the most recently processed ECG buffer.

## Processing Details

### ECG simulation and processing

The custom Wokwi chip constructs an idealized P-Q-R-S-T waveform using Gaussian components, reconstructs the waveform using Fourier terms, and adds small random noise and low-frequency baseline wander. The output is mapped to a bounded analog voltage.

On the ESP32 side, `CardialState`:
1. Samples GPIO 34 at a target 250 Hz rate.
2. Collects 2000 samples per processing window.
3. Applies a second-order 35 Hz low-pass filter.
4. Detects local maxima above an adaptive threshold, with a 350 ms refractory interval.
5. Calculates RR intervals and corresponding BPM values from detected peak locations.
6. Reports the average RR interval and average BPM for the processed window.

These are prototype signal-processing methods. The peak detector may miss peaks or identify false peaks depending on the signal and should be validated before use with real data.

### IMU and Kalman filtering

`InertialState` reads the MPU6050's accelerometer and gyroscope values. It calculates the elapsed time between updates, obtains an accelerometer-derived angle, and uses the gyroscope rate to predict orientation. `KalmanFilter` then corrects the predicted angle using the accelerometer measurement while estimating gyroscope bias.

The current implementation estimates one angle using the X-axis gyroscope rate and the `atan2(Ax, Az)` accelerometer angle. It is not a full 3D orientation estimator.

## Dependencies

- ESP32 Arduino core / Wokwi ESP32 simulation
- Wokwi MPU6050 component
- Wokwi custom-chip support for `ecgsim.chip.c`
- `MPU6050` Arduino library as declared in `libraries.txt`
- Arduino `Wire` and `Arduino` APIs
- ESP32 FreeRTOS APIs (provided by the ESP32 Arduino environment)

The custom chip is implemented using the Wokwi Custom Chips API. Running it outside Wokwi requires adapting or replacing that simulator-specific component.

## Current Scope and Limitations

- The ECG waveform is synthetic and controlled by a simulator slider.
- The ECG simulator's configured BPM and the firmware's detected BPM may differ because of sampling, filtering, and peak-detection behavior.
- The current firmware reports results over Serial; this folder does not implement a gateway, database, dashboard, wireless telemetry, or AI inference.
- The broader `project_req.txt` describes these as future implementation phases rather than features completed by this simulation.
- This prototype is intended for software experimentation and education, not clinical diagnosis or medical decision-making.

## Relationship to WearTwin

This simulation provides an early test environment for the acquisition and processing part of WearTwin before integration with physical wearable hardware. The broader project plan describes later work such as synchronized data storage, a Raspberry Pi gateway, feature extraction, readiness-state logic, AI inference, and casualty/recovery simulation. Those later capabilities should be treated as planned work unless implemented in other parts of the repository.
